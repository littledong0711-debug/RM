## 考核加权与技术要求（任务书参考）

- 游戏得分按难度加权：中杯×0.5、大杯×0.75、超大杯×1.0。满分对应50、75、100分。原始得分与加权得分分开记录。
- 代码规范性单列40分，不自动认定项目已经拿满，也不推断未说明的多难度汇总方式。
- OOP设计、Google C++ Style Guide规范；设计卡尔曼滤波器进行预测。当前实现有类封装和KalmanFilter，但代码风格是否完全合规需要独立审查。
- 图像话题/image_raw，1152×648；根据发射装置颜色判敌我，异色为敌、同色为友。
- 转向协议为0x01后接float32角度，范围-180至180度，0度水平向右；开火为0x02。PDF未明确字节序；当前代码使用little-endian，不把该实现细节当作文档明示要求。
- 游戏界面提供种子输入框，留空随机。建议记录种子并以相同种子比较档位，但同种子能否逐帧完全复现仍受游戏实现/时序影响，需实测。
- 三次命中击毁，不应把每次命中都按+5/-20计算。
- PDF提交段落写2026年3月10日22时前上传GitHub并发链接；该日期早于当前测试日期，仅保留为原文参考，需确认当前考核时间，不自动上传代码或发送链接。

数量是游戏生成规则，当前自瞄程序没有控制敌我生成数量的接口或硬编码数量；因此本次改的是项目规则记录，不是游戏二进制，也没有伪造数量参数。
已核对当前源码图像接口、600像素/秒弹速、颜色判定、三类跟踪/预测接口；本次不因新增文档信息调整预测/避让参数，balanced仍为0.03秒。

## 解释修正与优化约束

- 稀疏帧中的净降分不等于误伤：可能有敌方逃逸，也可能多个正负事件相抵。历史文档中“前段降分”不能当作误伤证据；用户直接报告的误伤次数仍单独保留。
- 一次普通友方误伤损失相当于完整击毁一个敌方的收益；击毁友方的最后一击损失相当于完整击毁两个敌方的收益。完整击毁友方合计损失相当于四个完整敌方收益。
- 放走一个敌方扣1分，低于一次友方普通误伤的5分；但长期弃射还有失去敌方命中收益的代价，不等于应无条件停火。
- 当前代码未识别目标剩余血量，也未按血量区分友方受伤与被击毁风险。不能声称已实现按本细则优化的期望分数策略。
- 已死亡目标离场不扣分，不代表其不挡子弹。当前没有独立灰块障碍检测/避让，碰撞行为仍需确认。
- 本轮只记录规则，未修改算法或参数；balanced敌方额外预测补偿仍0.03秒。
